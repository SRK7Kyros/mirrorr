## 0. Intent on record

**Card grids on Sessions, Autoruns and Recordings are a product decision, not drift.** They stay. `console-design-spec.md` §5/§7 said rows; that language is now marked **superseded** in the spec itself (dated override), so no future agent converts these pages to tables.

What this plan fixes is **the card**, not the grid. Profiles, Sources, Plugins and the admin tables are already lists and stay lists — that was never the complaint.

**Four corrections on record (5 Nov 2026, from you).**

1. **No effort estimates.** Phases are ordered by dependency; a day count was noise about a plan nobody has started. Removed everywhere.
2. **The card is a slot skeleton, not one fixed anatomy.** Earlier drafts forced every card to `strip + two lines`. That was wrong for the same reason the current screens are wrong: a live run, an autorun and a finished file are different objects. §2.2a now declares **six ordered slots** and a **recipe per surface** — Sessions shows a frame and a player, Autoruns shows its window block, Recordings shows a preview frame and a download. What stays identical is the **order** (status top-left, name bottom).
3. **"Few primitives" must not mean "less app".** Nothing the current cards tell you is deleted. Every value keeps a home — a slot or a stated one-click disclosure — and §7's **fact-inventory diff** is a build gate: a fact that disappears without a replacement fails the phase.
4. **Layout: uniform (decided), and my first rationale for it was wrong.** I argued a packed layout breaks reading and tab order. **That is only true of the manual-column variant** (`[1,4,7][2,5][3,6]` as *DOM* order); a real grid-lanes keeps CSS flow order row-major, so source order, tab order and `Load more` stay correct — the wrong claim is retracted in §2.2a. Uniform is still the answer, for two honest reasons: `grid-lanes` ships **only in Safari 26.4** (≈7 % global; Chrome/Edge/Firefox flag-only), so a Capacitor app would render two different pagings on iOS and Android; and the eye reads down a packed column, which makes "first" ambiguous in a newest-first list. **The condition that came with the decision: uniform must not turn into empty space reserved for content we do not have.** Hence the plate table in §2.2a — every `media` fill carries fields from the record, and a state that cannot produce three actionable values does not get a card.

## 1. Diagnosis — five causes, not seventy-one symptoms

The screenshot you sent is the whole app in one frame: two identical cards in a 1,160 px canvas, 425 px of empty page below, and the only thing separating "Scheduled" from "Running" is a chip at the bottom — while the schedule block above says `starting…` on one and nothing on the other.

Five structural decisions produce that everywhere:

**D1 · The card has no anatomy — each screen invented its own.**
The grid is fine; the card is doing four jobs (state, identity, time, actions) in a different order per page, with no fixed slots:

- *Sessions* card: `☐ #106 🗑` → 196 px black box with a status chip on its bottom edge → title → `— · not started` → *"No media yet — nothing published for this run."*
- *Scheduled* card: title → slug → **a box inside the box** (window + countdown + "stored UTC") → chain → an unlabelled `—` → status chip + `☐` + `⋯`

Two pages, two card languages, one shared grid. A card that must be re-read from scratch is what "cluttered" feels like: nothing is in a predictable place, so every card re-teaches itself.

**D2 · The card's biggest region carries nothing.** The 16:9 area is empty on every run without a live frame — 5 of 6 in the capture — and on scheduled cards the equivalent is the nested window panel. Both spend ~50 % of the card's pixels on a container.

**D3 · Every action is promoted to the surface.** Delete sits beside select; three "create" entries compete on Profiles; five actions sit on a run header; a red button labelled `Recording` (a *state*) is the loudest control on the page. Nothing is prioritised, so the primary job is invisible.

**D4 · State is asserted, not derived.** A completed run says "Waiting for the supervisor"; a card says `Scheduled` while the strip says "none pending"; `starting…` is rendered as if it were a countdown; a schedule edit reports success after dropping the field. Each panel computes its own truth.

**D5 · The shell never decided what it is.** Title twice (top bar + `h1`), three nav models (236 px sidebar / 48 px icon rail / bottom tabs), bottom nav over content on every phone route, 404 outside the shell, focus never moved on navigation.

## 2. The contract — rules every screen obeys

Numeric acceptance criteria for the whole redesign.

### 2.1 Page frame

| Concern | Rule |
|---|---|
| Content column | `--content-max: 1240px`, gutters `--s-6` (24) ≥768 / `--s-3` (12) <768. |
| Page head | `h1` + **one line** of description (≤100 chars). Teaching copy lives in the empty state. One primary action, right-aligned. |
| Top bar | Breadcrumb + live pill + bell + avatar. **No page title** (the `h1` owns it). Breadcrumb parent is a real link. |
| Nav | Two models: 236 px labelled sidebar ≥1024 · 200 px labelled sidebar 768–1023 · bottom tabs <768. No icon-only rail. |
| Bottom clearance | Scroll container gets `padding-bottom: calc(var(--bottomnav-h) + env(safe-area-inset-bottom) + var(--s-4))` <768; asserted per route. |
| Section | `Section` = `h2` + count + its own toolbar; separated by `--s-10`, never a border. |

### 2.2a Card surfaces — one skeleton, declared slots

The three operational surfaces share a **skeleton**, not a fixed shape. A card is a column of
**ordered slots**; each surface declares a **recipe** — which slots it uses and what fills them.
The order is identical everywhere, the content is not, because these three entities are not the
same thing: a live run has a frame and a player, an autorun has a time window and nothing to
play, a finished file has a preview frame and a download.

| # | Slot | Use | Sessions | Autoruns | Recordings |
|---|---|---|---|---|---|
| 1 | `header` | always | status chip · `⋯` | status chip · `⋯` | status chip · `⋯` |
| 2 | `media` | Sessions + Recordings, **always** | **one 16:9 box, filled, never empty**: live frame + `▶` · the published file's own first frame + `▶` · plate when neither exists | — (nothing exists before the run) | the file's first frame + `▶` when served · plate when not |
| 3 | `hero` | always | elapsed (live) · duration (spent) · exit reason + attempts (failed) | countdown `in 3 d 4 h` | duration |
| 4 | `detail` | per recipe, **≤1** | remux progress **line pinned inside `media`** — zero extra height | **window block**: start → end, local time + zone, duration, retirement note | — |
| 5 | `identity` | always | title · `chain → engine · #id` | title · `slug · chain` | title · `chain · size` |
| 6 | `footer` | per recipe | inline `Stop` while live (when it is the run's only sensible verb) | `Edit` / `Run now` shortcuts when the card is the working surface | `Download` · `Copy link` |

**What is fixed** — this is the part that stops it becoming the current mess:

| Rule | Why |
|---|---|
| Slot **order** is invariant, on all three surfaces and at all widths. | The eye learns one card, not three. |
| `header` always occupies the top edge, `identity` always the bottom edge. | Status and name are always in the same corner. |
| A slot with no content **collapses** — except `media`, which keeps its 16:9 box and changes **fill**. | The void was *empty*, not *reserved*. A card that changes height between live and spent makes the grid jump on every state transition. |
| **At most one `detail` slot**, and it must carry a value that appears in no other slot. | Stops "box inside the box" and duplicate status. |
| Facts are right-aligned, tabular, **2–4 per card** as the recipe declares. | Numbers scan as a column. |
| One status per card: the chip. Tone is decoration, the word carries the meaning. | No `LIVE` overlay, no second label. |
| **No fact is deleted.** Every value a card renders today keeps a home — a slot, or a stated disclosure one click away. | This is the guard against "clean" turning into "less". §7 gates it. |
| **Row-major source order** — 1·2·3, then 4·5·6 — at every width. Never assign items to columns by hand. | Hand-assignment (`[1,4,7][2,5][3,6]` in the DOM) makes tab order and visual order disagree (WCAG 2.4.3) and makes `Load more` reshuffle. CSS flow order keeps them aligned whether the grid is uniform or packed. |

**Uniform within a surface, different between surfaces.** Every Sessions card is the same height as
every other Sessions card; likewise Recordings, likewise Autoruns (which has no media, so it is a
shorter card — but uniform among its own kind). Height is a property of the **recipe**, not of the
item, so sorting, filtering and `Load more` never reshuffle the grid and nothing moves under the
cursor mid-scan. This is also why Sessions draws its remux `detail` *inside* the `media` box: the
card must not grow while a file is finalising.

**The `media` fill ladder — never a placeholder.** (1) a live frame while the run is live; (2) the
file's **own first frame** with `▶` once it is published — a muted `<video preload="metadata" src="…#t=0.1">`
positioned in the box, no ffmpeg pass and no new route; if metadata never loads it degrades to (3);
(3) a **plate** when there is no file to show, built from the record itself:

| State | The plate carries (real fields only) |
|---|---|
| starting · waiting for engine | elapsed since `started_at` · `resolver → engine` · `attempt n` · *waiting on the engine process* (the chip already says `Starting` — it is not repeated) |
| failed | **`captures[-1].reason`** — the actual error, 2 lines max · attempts used (`retry_attempts`) · bytes captured · *Retry lives in `⋯`* |
| finalising · remuxing | `recording_progress` as the pinned line · duration · *file kept* |
| completed, not published | duration · size · `ended_at` · *not published — why* (the publishing error, if the run recorded one) |
| pending from an autorun | countdown · window · `autorun_name` as a link |
| stopped by you | duration · size · stopped-at · *file kept* |

**No filler.** A plate value must be one an operator acts on — why it stopped, what it got, when, how
to retry. Decoration, a second status word or a repeated title never count as content. **If a state
cannot produce three such values, it does not get a card**: it belongs in the page's *needs attention*
line, not in a 16:9 box holding a gradient. That is the rule that stops "uniform" from becoming
"empty space because we had nothing to put there".

| Element | Rule |
|---|---|
| Grid | 3 columns ≥1280 · 2 columns 768–1279 · 1 column <768. Gap 14. Card min 300 / max 400 px. **`align-items: stretch`** — all cards in a surface share one height, and a row is a row. |
| Card size | Sessions / Recordings ≈ 300 px (16:9 + two text lines). Autoruns ≈ 230 px (hero band + window block + two lines). No card is ever sized to its content. |
| Narrow cards | Below ~360 px of card width the hero splits: headline + facts share one line, the label takes a full-width second line (`max-width: none`, still clamped to 2 lines). A real reason is never ellipsised to 90 px beside the facts; if it needs a third line it is not a card fact — it belongs on the detail page. |
| `media` fills | `frame` (live) · `cover` (published file's own first frame) · `plate` (no file). `remuxing` is not a fourth fill — it is a progress line pinned to the bottom edge of whichever fill is showing. The set is closed; a surface may not invent a new one. |
| Selection | No checkbox at rest. A toolbar **Select** toggle turns on per-card checkboxes + select-all in the toolbar; selection is scoped to visible cards and clears on filter/sort change ("N outside this filter"). |
| Actions | `⋯` in the header, 44 px hit (visual 26 px), text items, Delete below a divider. Whole card is the link; `⋯` stops propagation. A `footer` verb is legitimate only when it is the surface's primary action and does not duplicate a `⋯` item. |
| Toolbar | One row ≥900: segmented filter (`aria-pressed`), search (flex), sort, `Select`; wraps below 900 (search full width). One count. |
| Empty / error / loading | Skeleton **cards** matching the recipe's slot heights · `ErrorPanel + Retry` · `EmptyState` calling the page's action. A failed query never renders as "none". |
| Dense | `Load more` (cursor); auto-exhaust shows progress and failure. |

### 2.2b List surfaces — Profiles · Sources · Plugins · admin tables

These are already rows; they keep rows. Row height 44–52 px, semantic `<table>` ≥672 px, row-cards below, one `⋯` per row, selection scoped, one toolbar. No card grids here.

### 2.3 Detail pages — Session · Autorun

| Concern | Rule |
|---|---|
| Layout | ≥1024 two columns `minmax(0,2fr) / minmax(280px,1fr)` — player/timeline left, facts + actions right. <1024 one column, facts before history. |
| Header | `← parent` · title · `StatusPill` · **the current verb** (`Stop recording`, `Open recording`, `Retry`) · `⋯` overflow. Never a button labelled with a state. |
| One fact, one home | Every value appears **once**. Header subtitle = `profile → engine`. Config in a collapsed disclosure unless the run failed. |
| Conditioned panels | "Live sources" only while live; "Recording" only when a file exists; terminal runs never show live panels. |
| State | One `deriveRunState()` drives header, pill, panels, banners. A banner contradicting the pill is a bug. |

### 2.4 Vocabulary

| Concept | Term everywhere |
|---|---|
| A capture run | **Session** |
| A one-shot schedule | **Autorun** — nav label, page title and card copy all say Autoruns (decision 2B, 5 Nov 2026) |
| Reusable capture config | **Profile** |
| Saved resolver + config | **Source** |
| A finished media file | **Recording** |

`Presets` leaves the UI. The word **"Scheduled"** leaves the UI as an *entity name* (it already
survived only as a nav label); the route `/autoruns` stays, so no link or bookmark breaks. "Schedule"
survives only as ordinary English inside a sentence ("this autorun runs once, then retires") — never
as a label, heading or column name. `inventory.md`, `findings.md` and `doc-audit.md` keep the old
label because they describe the **current** build; this plan and everything built from it say
*Autoruns*. The status chip on a pending run still reads `Scheduled` — that is a state, not an entity.

### 2.5 Tokens & interaction

| Concern | Rule |
|---|---|
| Type | `--fs-base` (13) floor for body/row text; `--fs-xs` (11) only for uppercase labels; helper ≥12 px and ≥4.5:1. No 10–11 px grey prose. |
| Status tones | healthy = `--success` · scheduled = `--info` · transitional = `--warning` · failed = `--danger` · spent = `--neutral`. Record-red is reserved for the act of recording. |
| Contrast | input border ≥3:1, secondary text ≥4.5:1, focus ring 2 px + 2 px offset. |
| Targets | ≥44×44 coarse pointers, ≥24×24 elsewhere, ≥8 px gap between adjacent targets. |
| Focus | SPA navigation focuses `<main>` and announces it; skip link; `Field` binds `aria-invalid`/`aria-describedby`/`required`. |
| Motion | `prefers-reduced-motion` honoured (already implemented). |
| Destructive | Confirm naming the object **or** undo toast. Stop is confirmed. Never toast-only failure. |

## 5. Sequencing

Correctness before cosmetics; each phase is independently shippable. Order is by dependency, not
by size: **P1 must land before any card work**, because a card built on a state machine that
asserts the wrong status just puts the lie in a nicer box.

### P0 — Evidence harness

Extend the capture gallery to the **admin build** and the missing states (error, loading,
filtered-empty, denied) — 99 → ~130 shots. Regenerate `docs/ux-audit/screens/` as the "before"
baseline and add Playwright visual baselines per route × viewport. Add to CI: `check:tokens`,
`check:contrast`, axe on every route, target-size assertion, and the fact-inventory diff (§7).

**Exit:** a failing screenshot diff is the only way to claim "looks the same".

**Landed 6 Nov 2026.** One registry — `mirrorr-web/tests/visual/scenarios.ts` — describes every
state; four consumers read it and can no longer disagree about what "the app" is:

| Consumer | Command | Output |
|---|---|---|
| `gallery.spec.ts` | `bun run gallery` | `docs/ux-audit/screens/v{375,768,1280,1440}/*.png` (133 shots, regenerable) |
| `routes.visual.spec.ts` | `bun run test:visual` | pixel baselines in `tests/visual/__screenshots__/` |
| `a11y.spec.ts` | `bun run test:a11y` | axe (WCAG A/AA) + WCAG 2.2 target-size sweep, every width |
| `fact-inventory.spec.ts` | `bun run test:facts` | one assertion per value the three card surfaces render |

CI gained a `browser` job (Chromium, route-mocked — no backend) running the behaviour, accessibility
and fact-inventory suites; the pixel gate stays local because baselines depend on host font
rendering. The fact inventory is the executable version of §2.2a's "no fact is deleted" rule: its
`home` column records where each value lives, so a phase that moves a fact must edit that line, and a
phase that drops one fails.

## 6. Proven patterns being borrowed

| Decision | Borrowed from | Why it fits |
|---|---|---|
| Card per run with a **status strip + hero metric** | Home Assistant tiles, Grafana panel cards | A card earns its size when the top band carries a live artifact *or* a headline number; both shapes stay card-shaped. |
| **Fixed slot order, declared per surface** | Twitch stream manager, YouTube Studio, Home Assistant tiles | The card becomes learnable once — status always top-left, name always bottom — while a live run can still show a frame and an autorun can still show its window. |
| **One uniform card height per surface, filled rather than sized** | YouTube Studio video grid, Linear boards | The grid never reflows when a run changes state: the media box is a constant region whose *content* changes (live frame → file's first frame → plate), not its presence. |
| Countdown as the hero, never prose | Linear cycles, GitHub Actions | `starting…` → `in 3 d 4 h` is the same pixel budget spent usefully. |
| `⋯` overflow, destructive last | Stripe Dashboard | One action surface; delete never adjacent to a target the user aims at. |
| Select-mode instead of resting checkboxes | macOS Photos, Linear | Removes the checkbox+trash cluster that eats card width. |
| One toolbar per page | Grafana, Vercel | Kills the second search box and the duplicate refresh. |
| Collapsed config with copy | Vercel project settings | Keeps JSON out of scan surfaces without hiding it. |

## 7. Verification

- **Unit:** `EntityCard` slot contract (order, collapse, ≤1 `detail`), each surface recipe, each `media` fill (frame/cover/plate + the remux line), `CardGrid` breakpoints, `deriveRunState`, selection scoping, time/timezone, query states.
- **Plate content, asserted:** one snapshot per `media` state proves each plate renders ≥3 fields from the record, at least one of them the reason or a measurement — a plate that renders only a glyph and a word fails. The state → fields map lives in one table (§2.2a), not in each view.
- **Uniform height, asserted:** a test measures every card in a rendered grid at 375/768/1440 and fails on any outlier. State changes (live → spent, cover → plate, remux start/finish) must not change a card's height — that is the whole point of decision 1.
- **e2e:** happy + failure path per flow; keyboard-only pass per screen; no focus trap outside dialogs.
- **Visual:** route × {375, 768, 1440} baselines; before/after pairs per phase; the §P2 gallery is the reference set for every slot state.
- **Fact-inventory diff — the gate against over-simplification.** For each of the three card surfaces, enumerate the values the *current* card renders (from the code and the before-screenshot): `#id`, title, status, chain, profile, elapsed/duration, attempts, size, remux progress, window, countdown, slug, serve-state, actions. The build must render each one in a slot or reach it through a stated disclosure. A value that disappears with no replacement fails the phase. This is a test, not a review note.
- **Automated gates:** `check:tokens`, `check:contrast`, axe per route, target-size assertion, and a grep gate that fails on a card surface containing its own `repeat(auto-fill` (the grid must come from `CardGrid`) — the gate is about *duplicated layout logic*, not about card height or slot count.
- **Manual:** I re-shoot the gallery each phase and put before/after pairs in the PR.

## 8. Risks and containment

| Risk | Containment |
|---|---|
| **"Few powerful primitives" turning into "less app"** — a slot skeleton becomes an excuse to drop the facts that made the card useful | The fact-inventory diff (§7) is a build gate, not a code review: a value that vanished without a stated home fails the phase. §2.2a's "no fact is deleted" rule is what every recipe is checked against. |
| One `EntityCard` becomes a god-component with a flag per surface | The card renders slots; the **recipe** is data, not branches. If a surface needs a seventh slot, that is a design decision recorded here, not a prop. |
| Slots drift back into per-card invention | Slot order and edges are unit-tested, not just designed; the gallery renders every state. |
| 19 unit test files + 14 e2e specs assert current card markup | Rewrite per phase with the page; every deleted assertion gets a replacement. Visual baselines are the backstop. |
| `session-card.tsx` nested-interaction guard is good code | Its behaviour (buttons inside a clickable card) moves into `EntityCard` with its test. |
| `Run now` needs a core change | Optional field, default `None`; the scheduler already writes `autorun_id` (`autorun_scheduler.py:91`), so only the create path changes. |
| Uniform cards waste space when a run has no preview | No: the `media` box is filled by live frame → the published file's first frame → plate, and the plate carries fields from the record (why, how many attempts, how many bytes, when it starts). The space is only "wasted" if it is empty, which is the current bug. The alternative — masonry — costs sort order, tab order and cursor stability (§0.4). |
| A new state arrives that has no `media` fill | The fill set is closed (`frame` · `cover` · `plate`, plus the pinned remux line). A new state maps to a plate with real fields — it does not get a new card shape. |
| Few items make a 3-col grid look empty | Cards max 400 px so they don't stretch; the head carries the count and the `needs attention` line, which is what a sparse page is for. |
| Scope creep into visual redesign | Tokens, palette, type and "Control Room" direction stay. This changes structure, hierarchy and copy. |

## 9. Not doing

- No tables on the three card surfaces (that is the point of §0).
- **No feature or fact removed for the sake of visual calm.** Anything the current card tells you stays reachable on the card; only the *duplication* and the *empty containers* go.
- No light theme, no palette or font change.
- No new backend endpoints beyond optional `autorun_id` on session create.
- No virtualisation or infinite scroll (cursor + Load more stays).
- No mobile-native redesign; Capacitor keeps wrapping the same app.
- No route renames (`/autoruns` stays; the UI now says **Autoruns**, so route and label finally agree).
- **No masonry, no column-major packing, no variable card heights.** Uniform per surface, row-major, `align-items: stretch` (§0.4).
- **No server-side thumbnail pipeline.** The published fill is the file's own first frame rendered by a muted `preload="metadata"` `<video>` in the box — no ffmpeg pass at finalise, no new route, no cache to invalidate. If a card list of many videos ever costs too much (measured, not assumed), the upgrade is a single ffmpeg extraction at finalise behind `MediaFill`, and the card does not change.
