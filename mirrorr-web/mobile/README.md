# Mirrorr iOS shell

A Capacitor 8 wrapper that is deliberately a **remote shell**: the only bundled
content is the server picker in `launcher/`. Choosing a server loads that host's
live console in the WebView, so the console runs from its own origin and its
cookies, `/api` and `/ws` behave exactly as they do in a browser — which is what
makes "stay signed in per server" work without storing passwords anywhere.

## Layout

| Path | Role |
| --- | --- |
| `launcher/` | The app's home page: host list, add/remove, tap to connect (`webDir`). |
| `ios/`, `android/` | Generated by `bunx cap add ios` / `cap add android`; gitignored, never committed. |
| `../mobile.html` | Document of record for a *bundled* build (viewport-locked). Unused by the remote shell; kept as the seam for an offline variant. |

Hosts are stored natively (`@capacitor/preferences`, with a `localStorage`
fallback when the page is opened in a plain browser). Sessions are not stored by
the app at all: each host's refresh cookie lives in the WebView's own cookie
store, which iOS keeps per origin and persists across launches.

## Build the IPA

There is no local build path — Xcode only exists on macOS. The `iOS Sideload IPA`
workflow (`.github/workflows/ios-sideload.yml`) does it on a GitHub runner:

```bash
gh workflow run ios-sideload.yml --ref main
gh run download --name mirrorr-ipa    # Mirrorr.ipa, unsigned, for Feather/AltStore/Sideloadly
```

Locally you can only verify the shell wiring, and only where CocoaPods is not
required:

```bash
bunx cap add ios      # generates mobile/ios from the template
bunx cap sync ios     # copies mobile/launcher -> ios/App/App/public
```

Switching servers: the picker is the app's launch page, so reopening the app
returns to it; each server is still signed in.
